# Contributing

## Language

Use English for all repository content, documentation, examples, code comments,
commit messages, issues and pull requests. Translate source material from other
languages faithfully and identify it as a translation.

Start with a concrete problem, use case or counterexample. Small documentation
fixes can go directly to a pull request. For changes to core concepts, governance
or the future contract format, discuss an issue and use the [RFC process](rfcs/README.md).

1. Read [licensing status](LICENSING.md) before contributing reusable material.
2. Fork the repository and create a descriptive branch from `main`.
3. Make a focused change. Explain the problem, expected outcome and limitations.
4. Check relative links, terminology and any affected examples or build commands.
5. Open a pull request describing the change and how you checked it.

Only submit material you are entitled to share publicly. Use fictional examples.
Do not include internal documents, customer information, credentials or personal
data. AI-assisted contributions are welcome; the contributor remains responsible
for accuracy, source rights and verification. Explain substantial AI assistance
when it helps reviewers understand how the contribution was produced.

Maintainers record substantive decisions in issues, pull requests or RFCs.
Disagreement with a proposal is welcome; explain the consequence and an alternative.
Follow the organization's community conduct guidance.
