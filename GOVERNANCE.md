# Governance

Status: founding governance proposal, to take effect when merged.

## Responsibility

The initial maintainer is [Azmir Abdi (@azmirabdi)](https://github.com/azmirabdi).
Contributors can propose changes without membership in the GitHub organization.
Maintainers review changes, manage releases and explain decisions publicly.
This project does not currently claim foundation governance, multi-vendor control
or standards-body status.

## Decisions

Routine corrections use pull requests. Changes to principles, public contract
semantics, compatibility, licensing or governance require an RFC. Allow at least
seven calendar days for comments on substantive RFCs before accepting them.
The maintainer records the outcome, reasoning and unresolved objections in the RFC.
Silence is not evidence of community agreement. Decisions can be revisited through
a new RFC with new evidence or a concrete alternative.

During the single-maintainer phase the maintainer can merge their own reviewed
pull request after recording checks. Once a second active maintainer is appointed,
the project will propose independent review requirements and update branch rules.
No document in this repository claims that a GitHub protection rule is enabled.

## Maintainer changes and conflicts

Nominate maintainers through a public issue describing sustained contributions
and willingness to review and maintain the project. Use the same seven-day review
period and record the decision. Maintainers should disclose relevant commercial
interests and seek another reviewer where they have a conflict. If independent
review is unavailable, record that limitation explicitly.

## Releases

Whitepaper revisions and specification versions are distinct. Draft examples do
not establish compatibility promises. A specification release requires documented
scope, versioning rules, examples and executable conformance checks. Governance
changes follow this same public RFC process.
